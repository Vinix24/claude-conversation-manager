## Drie features voor v0.2

### Feature 1: Headless `-p` sessies wegfilteren

**Probleem**: `claude -p` subprocess-dispatches (VNX-workers, automation-scripts) vervuilen de sessielijst.

**Aanpak**: detectie via combinatie van heuristieken, kolom `session_type` toevoegen aan SQLite-index, UI-toggle "Hide headless sessions" (default aan).

**Heuristieken** (allemaal configureerbaar in `config.py`):

| Signaal | Default-drempel |
|---|---|
| Aantal turns | `< 4` → headless-kandidaat |
| Eerste user-message patroon | bevat `# Dispatch:`, `## Critical rules`, `dispatch_id`, etc. |
| Werkdirectory | bevat `-wt-`, `/worktree/`, `/.claude/terminals/` |
| Sessie-duur | `< 60s` tussen first en last message |

Score = som van signalen. Drempel default 2: bij ≥ 2 signalen markeren als `headless`.

**Schema-migratie**:
```sql
ALTER TABLE conversations ADD COLUMN session_type TEXT DEFAULT 'unknown';
ALTER TABLE conversations ADD COLUMN session_type_score INTEGER DEFAULT 0;
CREATE INDEX idx_conversations_type ON conversations(session_type);
```

**Backfill**: één run over bestaande sessies bij eerste upgrade.

**Test**: kalibreer drempel door sample van mijn 860+ sessies (zie `~/.claude/projects/`) waarvan ik weet welke headless zijn (alle `T1`/`T2`/`T3` mappen + alle worktree-paden zijn headless).

### Feature 2: "Actief laatste X dagen" filter

**Probleem**: alle sessies van het laatste jaar zien is meestal niet wat ik wil. Default-view zou recent moeten zijn.

**Aanpak**: dropdown of segmented control in de UI:

- 1 dag
- 7 dagen
- 30 dagen (default)
- 90 dagen
- Alles

**Backend**: één extra `WHERE last_message >= datetime('now', ?)` clause. Index `idx_conversations_last_message` bestaat al.

**Persistentie**: keuze opslaan in localStorage of `config.py`. Mijn voorkeur localStorage zodat het per gebruiker is.

**Tijd**: halve dag inclusief tests. Kleinste werk van de drie.

### Feature 3: Haiku-gegenereerde session titel

**Probleem**: huidige titels komen uit cwd of eerste user-message. Voor mij niet betekenisvol genoeg. Wil zien "Renewance Blueprint creation" of "Sentech demo prep" in plaats van `/Users/vincentvandeth/Desktop/BUSINESS/...`.

**Aanpak**:

1. **Sampling per sessie**: eerste 3 user-messages + eerste assistant-message, capped op ~2000 tokens.
2. **Call via `claude -p` subprocess** (geen Anthropic SDK, conform mijn `no-anthropic-sdk` constraint):
   ```bash
   claude -p --model claude-haiku-4-5-20251001 --output-format json <prompt>
   ```
3. **Prompt-template**:
   ```
   Vat het onderwerp van dit gesprek samen in maximaal 6 woorden.
   Geen volledige zin, geen punt aan het eind.
   Voorbeelden:
   - "Renewance Blueprint creation and finetuning"
   - "Sentech demo prep"
   - "VNX tmux restore investigation"
   Antwoord alleen met de samenvatting, niets anders.
   ```
4. **Schema-uitbreiding**:
   ```sql
   ALTER TABLE conversations ADD COLUMN summary TEXT;
   ALTER TABLE conversations ADD COLUMN summary_model TEXT;
   ALTER TABLE conversations ADD COLUMN summary_generated_at TIMESTAMP;
   ```
5. **Skip-logica**: regenereer alleen als `summary IS NULL` OF sessie-grootte sinds laatste summary substantieel groter.
6. **Backfill-kosten**: ~860 sessies × ~500 input tokens × Haiku 4.5 prijs = onder de €0.20 eenmalig. Incrementeel cents per week.
7. **Async pipeline**:
   - Indexer pakt nieuwe/gewijzigde sessies → enqueue in een `summary_queue` tabel
   - Background-worker (thread in `app.py`) draait queue af op 1 call/sec, retry on rate-limit
   - UI toont "Summarizing..." placeholder tot het klaar is
8. **Config-keuze** in `config.py`:
   ```python
   SUMMARY_PROVIDER = "claude-cli"  # "claude-cli" | "ollama" | "none"
   SUMMARY_MODEL = "claude-haiku-4-5-20251001"
   SUMMARY_MAX_WORDS = 6
   ```
   Ollama-optie blijft hint voor gebruikers zonder Anthropic-account (kan ik later toevoegen, niet in v0.2 scope).
9. **Display**: titel-regel = summary, pad + session-uuid in kleinere secundaire regel eronder.

## Bonus: search UX fix

**Probleem**: bij meerdere zoekwoorden gaat de auto-`*` UIT (want spatie is special char). Dus `renier opg` doet geen prefix-match.

**Fix**: in `app.py:152-153` slimmer detecteren. Pseudocode:

```python
if any(char in fts_term for char in '"+-'):
    fts_query = fts_term  # raw FTS5 query, user knows what they want
else:
    # auto-prefix per woord
    fts_query = " ".join(w + "*" for w in fts_term.split())
```

Effect: `renier opg` wordt `renier* opg*` en matcht `renier opgplastic`. Power-users met `"phrase"` of `OR` blijven ongemoeid.

Eén PR, paar regels.
