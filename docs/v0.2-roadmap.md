# v0.2 Roadmap — Claude Session Dashboard

> Opgesteld 2026-05-19 als pickup-document voor de volgende werksessie. Drie features die de manager van bruikbaar-voor-mij naar bruikbaar-voor-elke-Claude-Code-gebruiker tillen, plus één UX-fix in search.

## Positioneringsbesluit

Niet samenvoegen met VNX dashboard `/conversations`. Twee doelgroepen:

- **claude-conversation-manager**: elke Claude Code gebruiker die zijn sessies wil terugvinden en hervatten. MIT, broad appeal.
- **VNX dashboard `/conversations`**: koppelt sessies aan VNX-dispatches en gates. Niche.

Alle features hieronder horen in conversation-manager. VNX kan later via een optionele importer dezelfde SQLite-index lezen.

## Drie features voor v0.2

### Feature 1: Noise filteren — herontwerp nodig (2026-05-19)

**Status**: eerste poging als PR #5 gebouwd en weer gesloten zonder merge. Branch `feat/headless-session-filter` blijft als referentie. Reden: het oorspronkelijke ontwerp hieronder ging uit van een verkeerde aanname.

**Wat er mis was met de eerste aanpak**

De heuristiek gebruikte dispatch-markers (`# Dispatch:`, `dispatch_id`, `VNX_DISPATCH`, `Task ID:`, `## Critical rules`) als signaal voor "dit is headless ruis, verbergen". Dat is precies verkeerd om: T0 dispatcht workers in échte project-directories en die subprocess-runs zijn juist het belangrijkste deel van mijn productie-verkeer. Calibratie op 9562 sessies gaf 86% headless-classificatie — dat is niet 86% ruis, dat is 86% legitiem worker-werk dat verborgen zou worden.

**Wat ik echt wil filteren** (twee categorieën, niet één)

| Categorie | Voorbeelden | Default-gedrag |
|---|---|---|
| **Ruis** | `echo ok` keepalives, `/exit`/`/model`/`/clear` slash-only sessies, terminal-spawn boilerplate uit `~/.claude/terminals/`, lege/aborted sessies | verbergen |
| **Subprocess-werk** | T0 → worker dispatches met dispatch-markers, tool-use, echte project-cwd | tonen |
| **Interactief** | normale Claude Code sessies door mij | tonen |

**Signalen-shortlist voor v2-ontwerp**

Voor *ruis* (positieve hit = verbergen):
- `cwd` bevat `/.claude/terminals/` zonder verdere project-context
- `cwd` is `$HOME` of een system-pad (geen project)
- `total_tokens == 0` of zeer laag
- Geen `tool_use` messages
- `message_count <= 2` AND first prompt is slash-only (`/exit`, `/model`, `/clear`, `/quit`, `/help`)

Voor *legitiem subprocess-werk* (positieve hit = tonen, **inverteert** de eerdere logica):
- Dispatch-markers in eerste prompt
- `cwd` valt onder een geregistreerd project uit VNX Orchestration registry
- Heeft `tool_use` messages
- Heeft inhoudelijke assistant-responses

**Open vragen voor het herontwerp**

1. Project-registry uitlezen of statische lijst in config? VNX Orchestration registreert projecten ergens — die als source of truth gebruiken zou kunnen.
2. Worden ruis en subprocess-werk twee aparte filter-toggles, of één gecombineerde "Hide noise" met smart-defaults?
3. Per-project zichtbaarheid: is "hide noise" globaal genoeg, of wil ik per project kunnen tunen?

**Schema-aanpak (waarschijnlijk overlevend uit v1)**

Drie kolommen op `conversations` (`session_type`, `session_type_score`, `session_type_signals`) zijn op zich generiek genoeg om hergebruikt te worden — alleen de scoring-logica in `headless.py` moet anders. Schema-migratie kan dezelfde patronen volgen.

**Afhankelijkheid**

Feature 3 (Haiku-summaries) wacht op dit herontwerp af. Zonder zinvolle filter zou je 9000+ summaries genereren voor sessies die je niet eens wilt zien — niet duur maar wel zinloos.

### Feature 2: "Actief laatste X dagen" filter

### Feature 3: Haiku-gegenereerde session titel

**Probleem**: huidige titels komen uit cwd of eerste user-message. Voor mij niet betekenisvol genoeg. Wil zien "Renewance Blueprint creation" of "Sentech demo prep" in plaats van `/Users/vincentvandeth/Desktop/BUSINESS/...`.

**Aanpak**:

1. **Sampling per sessie**: eerste 3 user-messages + eerste assistant-message, capped op ~2000 tokens.
2. **Call via `claude -p` subprocess** (geen Anthropic SDK, conform mijn `no-anthropic-sdk` constraint):
   ```bash
   claude -p --model claude-haiku-4-5-20251001 --output-format json <prompt>
   ```
3. **Prompt-template**:
   ```
   Vat het onderwerp van dit gesprek samen in maximaal 6 woorden.
   Geen volledige zin, geen punt aan het eind.
   Voorbeelden:
   - "Renewance Blueprint creation and finetuning"
   - "Sentech demo prep"
   - "VNX tmux restore investigation"
   Antwoord alleen met de samenvatting, niets anders.
   ```
4. **Schema-uitbreiding**:
   ```sql
   ALTER TABLE conversations ADD COLUMN summary TEXT;
   ALTER TABLE conversations ADD COLUMN summary_model TEXT;
   ALTER TABLE conversations ADD COLUMN summary_generated_at TIMESTAMP;
   ```
5. **Skip-logica**: regenereer alleen als `summary IS NULL` OF sessie-grootte sinds laatste summary substantieel groter.
6. **Backfill-kosten**: ~860 sessies × ~500 input tokens × Haiku 4.5 prijs = onder de €0.20 eenmalig. Incrementeel cents per week.
7. **Async pipeline**:
   - Indexer pakt nieuwe/gewijzigde sessies → enqueue in een `summary_queue` tabel
   - Background-worker (thread in `app.py`) draait queue af op 1 call/sec, retry on rate-limit
   - UI toont "Summarizing..." placeholder tot het klaar is
8. **Config-keuze** in `config.py`:
   ```python
   SUMMARY_PROVIDER = "claude-cli"  # "claude-cli" | "ollama" | "none"
   SUMMARY_MODEL = "claude-haiku-4-5-20251001"
   SUMMARY_MAX_WORDS = 6
   ```
   Ollama-optie blijft hint voor gebruikers zonder Anthropic-account (kan ik later toevoegen, niet in v0.2 scope).
9. **Display**: titel-regel = summary, pad + session-uuid in kleinere secundaire regel eronder.

## Bonus: search UX fix

**Probleem**: bij meerdere zoekwoorden gaat de auto-`*` UIT (want spatie is special char). Dus `renier opg` doet geen prefix-match.

**Fix**: in `app.py:152-153` slimmer detecteren. Pseudocode:

```python
if any(char in fts_term for char in '"+-'):
    fts_query = fts_term  # raw FTS5 query, user knows what they want
else:
    # auto-prefix per woord
    fts_query = " ".join(w + "*" for w in fts_term.split())
```

Effect: `renier opg` wordt `renier* opg*` en matcht `renier opgplastic`. Power-users met `"phrase"` of `OR` blijven ongemoeid.

Eén PR, paar regels.
